# حضرموت اليمني — نظام طلبات وإدارة مطعم

واجهة Next.js عربية مع سلة، طلبات محفوظة، لوحة إدارة محمية، واجهة تواصل وخريطة تفاعلية، ومساعد لتخطيط الوجبات حسب العدد والميزانية.

## تشغيل المشروع

يتطلب Node.js 24 أو أحدث لدعم SQLite المدمج.

    npm install
    npm run setup:owner
    npm run dev

- الموقع: http://localhost:3000
- الإدارة: http://localhost:3000/owner

ينشئ أمر إعداد الإدارة كلمة مرور قوية، ويخزن تجزئتها فقط في .env.local. بيانات الدخول للمستخدم محفوظة في OWNER-ACCESS.txt. لا يُنشر هذان الملفان ولا قاعدة البيانات ضمن الملفات العامة. يحافظ الأمر على الحساب الموجود إذا شُغّل مجددًا.

## عرض المميزات

1. مساعد اللّمة يقارن ثلاث طرق لترتيب وجبات الدجاج بناءً على عدد الأشخاص وميزانية الطعام، ويستخدم أسعار المنيو الحالية. الحصص تقديرية ومذكورة للزبون. لا يتجاوز الميزانية، وتضاف الوجبات للسلة بكمياتها.
2. تأكيد الطلب يحفظه في قاعدة بيانات المطعم ويعطي الزبون رقمًا مرجعيًا. فتح واتساب خيار إضافي وليس شرط وصول الطلب إلى اللوحة.
3. لوحة الإدارة تعرض الطلبات النشطة والمكتملة، وإجمالي قيمة المكتمل اليوم، والأصناف الأكثر طلبًا من الطلبات المكتملة فقط.
4. المدير ينقل الطلب من الانتظار إلى التحضير ثم الجاهزية والتوصيل والتسليم، أو يلغيه. لا توجد انتقالات آلية أو أوقات وصول وهمية.
5. تحديث السعر والتوفر وأجور المناطق من لوحة الإدارة. يمكن إيقاف استقبال الطلبات مؤقتًا.
6. طباعة فاتورة الطلب، وتنبيه صوتي اختياري عند وصول طلبات جديدة أثناء فتح اللوحة.
7. اسم المطعم والهاتف والواتساب والإنستغرام وخريطة تفاعلية تظهر في أول واجهة، مع زر لفتح الاتجاهات.

## البيانات والخصوصية

قاعدة البيانات الافتراضية: .data/hadramout.sqlite. يمكن تغيير موقعها بواسطة HADRAMOUT_DB_PATH. الأصناف والمناطق في lib/restaurant.ts وlib/delivery-areas.json تستخدم للتهيئة الأولى؛ التغييرات التشغيلية اللاحقة تُدار من اللوحة وتُحفظ في القاعدة.

عند التأكيد تُحفظ تفاصيل الطلب واسم الزبون ورقمه وعنوانه وملاحظاته. السلة المحلية لا تحفظ هذه البيانات الشخصية. بيانات الطلب متاحة لإدارة المطعم فقط بعد تسجيل الدخول. لا يوجد مسار عام للاستعلام عن الطلبات.

الدخول يستخدم تجزئة scrypt وجلسة في Cookie محمية HttpOnly/SameSite، وتُلغى الجلسة بالخروج وتنتهي خلال 12 ساعة. تحقق الأسعار والكميات يجري على الخادم. تكرار نفس محاولة التأكيد لا يُنشئ طلبًا مكررًا. عند تغير الأسعار بين المراجعة والتأكيد يُطلب من الزبون مراجعة المجموع مجددًا.

## التشغيل المنشور

    npm run build
    npm start

انشر على خادم Node.js مع قرص دائم وHTTPS. يجب الاحتفاظ بمجلد .data ونسخه احتياطيًا باستخدام أداة SQLite متوافقة، وضبط OWNER_PASSWORD_HASH على الخادم. لا تستخدم static export أو بيئة ملفات مؤقتة لقاعدة البيانات. هذه النسخة تستخدم SQLite محليًا؛ عند تشغيل نسخ متعددة من التطبيق يجب نقل البيانات إلى خدمة قاعدة بيانات مشتركة.

لوحة الإدارة تتحدث كل 10 ثوانٍ، والمنيو كل 20 ثانية أو عند العودة إلى النافذة. التنبيه الصوتي يحتاج تفعيل الزر وفتح اللوحة؛ ليس إشعارًا هاتفيًا عند إغلاق المتصفح. لا توجد بوابة دفع أو إرسال واتساب آلي.

## فحص النظام

    npm test

الأمر يبني نسخة الإنتاج ثم يشغّل فحص المتصفح على المنفذ 3101 مع قاعدة بيانات QA منفصلة. لا تُرسل رسائل إلى المطعم ولا تُخلط بيانات الفحص مع طلباته. يستخدم Microsoft Edge المثبت محليًا. ملفات QA محفوظة داخل .data باسم qa-* ويمكن تنظيفها بعد إغلاق خادم الاختبارات.

الفحص يشمل: الدخول والخروج ومنع الوصول غير المصرح، الأسعار والتوفر وأجور المناطق وإيقاف الطلبات، عدم تكرار الطلب، منع العبث بالأسعار، الانتقالات بين الحالات، إلغاء الوصول العام لحالات الطلبات، معلومات التواصل والخريطة، مساعد اللّمة، السلة، وشاشات الموبايل والكمبيوتر.

## أهم الملفات

- app/owner/page.tsx: لوحة الإدارة.
- components/RestaurantWelcome.tsx وapp/landing.css: الواجهة الرئيسية والتواصل والخريطة.
- components/GatheringPlanner.tsx: مساعد اللّمة.
- components/Cart.tsx وcomponents/OrderSubmit.tsx: السلة والتأكيد.
- lib/store.ts: التخزين، إعدادات المنيو، الطلبات والإحصاءات.
- lib/owner-auth.ts: الدخول والجلسات والتحقق من الطلبات.
- app/features.css: تصميم الإضافات.
